# 独立实现融合路线

本路线参考 [ManageBac-Dashboard 的公开功能说明](https://github.com/OscarOZK/managebac-dashboard)，只按功能需求独立实现，不复制其源代码、图片、文案或私有数据。CampusDesk 原有能力、数据格式和用户设置均保留；相同能力优先增强现有入口，不再增加重复页面。

## 能力映射

| 功能域 | CampusDesk 现有能力 | 融合方向 |
| --- | --- | --- |
| 待办、课程、成绩、Teams | 已有课程表、校历、调课规则、Teams/ManageBac 任务、反馈、双 GPA 与双 K 线 | 保留现有数据模型和页面，吸收可用的提醒与速览交互，不迁走或替换现有模块 |
| 提醒 | 已有 Teams 截止提醒、提前时间和本机通知 | 按学科筛选已同步任务；后续增加免打扰时段、提醒类型和汇总策略，全部默认保守、可关闭 |
| 外观 | 已有经典/卡片两种布局和 Liquid Glass | 独立增加一组颜色主题；布局切换与颜色主题互不覆盖，保留减少动效和可读性约束 |
| 快速查看 | 已有 macOS 状态栏菜单和主窗口 | 扩展为课程、近期任务、截止时间和同步新鲜度的紧凑速览，仍由同一进程和同一份本机数据提供 |
| 学习助手 | 已有全局搜索、今日计划、专注模式和变化记录 | 分阶段加入按需学习问答；先定义隐私、上下文范围与本地降级，再选择可选模型服务，不默认上传学校数据 |
| Apple Watch 与小组件 | 尚未实现 | 另建只读伴侣目标，复用经过验证的本机摘要；明确同步方式、设备要求和离线状态后再交付 |
| 跨设备推送 | 尚未实现 | 作为可选、自托管能力评估；不默认启用服务器，不上传登录会话、学校网页内容或附件 |

## 阶段与验收

### 第一阶段：提醒偏好

- [x] 新增 Teams 作业提醒学科白名单；空白表示全部学科，旧版状态自动默认全部。
- [x] 更新设置界面，支持恢复全部学科；过滤只改变通知计划，不删改作业或消息。
- [x] 覆盖中英文标签、旧状态校验和通知筛选回归测试。
- [ ] 扩展免打扰时间和提醒类型，确认跨时区、跨午夜与应用退出后的系统通知行为后再实现。

验收条件：旧备份能导入；过滤、恢复全部、任务完成和关闭通知都能正确更新系统待办通知；不改变学校同步快照；中英文均无残留文案。

### 第二阶段：主题与无障碍

- [x] 加入自然绿、海湾蓝、暖阳橙、深夜四套配色；旧备份缺失主题时继续使用自然绿，并保持经典/卡片布局选择独立。
- [x] 主题只改变展示，不改变 GPA K 线涨跌颜色、逾期/警告语义或学校数据；主题名称与说明支持中英文。
- [x] 针对常规浅色主题和深夜主题加入文本/按钮/选中导航 WCAG AA 对比度自动测试；主题选择控件在窄窗口调整列数，并尊重减少动效、减少透明度系统偏好。
- [x] 深色主题为系统控件使用 dark color-scheme；图表维持清晰的高对比绘图区，状态卡片保留独立语义色。

验收结果：Mac 端核心、界面、图表及来源测试套件通过；原生应用构建成功。未安装或发布，Windows 范围未改动。

### 第三阶段：状态栏速览

- 在现有状态栏入口扩展紧凑面板，而不是另起常驻同步进程。
- 展示下一节课、最紧急待办、近期截止时间和各数据源最近读取状态。
- 点击内容可回到 CampusDesk 对应原页面；缓存过期或同步不完整时明确标示。

### 第四阶段：学习助手

- 明确可发送的数据类别、逐次授权、清除记录与禁用选项。
- 不请求或保存学校密码；模型/API 凭据使用本机安全存储，不进入备份或日志。
- 没有外部服务配置时仍可使用搜索与计划功能；结果附来源并可跳回原页面。

### 第五阶段：Watch、小组件与可选推送

- 先定只读数据摘要和本机/用户 iCloud 同步边界，再独立构建 Apple Watch 与小组件目标。
- 推送服务必须可选、自托管、最小化保存，并提供关闭、撤销和删除说明。
- 每阶段需在实际目标系统与设备验收；无法验证的设备能力不能标为完成。

## 变更保护

- 每阶段分别运行核心、界面和原生构建测试，测试本机状态升级、导入/导出及通知取消。
- 不覆盖现有用户数据、未提交改动、Windows 目录或旧功能；保持 Windows 范围不变。
- 未经用户明确要求，不发布 GitHub Release，不替换本机安装，也不配置第三方服务。
